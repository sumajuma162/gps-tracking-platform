# Technical decisions

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-01 | Built Phase 0 together with the protocol core of Phase 3 (decoders, normalization, listeners with storage behind interfaces). | The decoders are pure and have no database dependency, and they are the highest-risk part. Proving them early against Teltonika's own example packets reduces risk. PostgreSQL storage stays in Phase 3, after the Phase 2 schema. |
| 2026-10-01 | Gateway code lives in the installable package `gpsgw` (`gateway/gpsgw/...`) instead of top-level `protocols/` and `services/` packages. | Top-level package names like `protocols` collide easily. An installable package is also required for the `gps_platform.protocols` entry-point plugin group (spec A6). |
| 2026-10-01 | Test fixtures are the byte-exact examples from https://wiki.teltonika-gps.com/view/Teltonika_Data_Sending_Protocols (fetched 2026-10-01). | Spec A5 requires the official packets. They cover Codec 8 (3 examples), Codec 8E, Codec 16 (used for the rejection test), UDP Codec 8 and 8E, and Codec 12 command/response. |
| 2026-10-01 | Records that fail validation (future/ancient timestamp, out-of-range coordinates) are counted in the ACK but not stored. | Teltonika resends until the ACK equals the record count. Leaving bad records unacknowledged would make the device resend them forever and block its queue. Rejections are counted per reason in gateway stats. |
| 2026-10-01 | A single `0xFF` byte on an open Teltonika TCP link is treated as a keepalive. | Some firmware sends it. It is ignored safely and produces no ACK. |
| 2026-10-01 | The gateway memory storage refuses to start unless `GATEWAY_ALLOW_MEMORY_STORAGE=1`, and `GATEWAY_STORAGE=postgres` exits with a clear error until Phase 3. | Prevents ACKing records that are not durably stored (spec A4.1) in any real deployment. |
| 2026-10-01 | All packet IMEIs are accepted syntactically (8-17 digits). The Luhn check applies only when an administrator registers a device. | The registry, not the parser, decides acceptance, so a typo'd registration does not silently drop a real device. |
| 2026-10-01 | Pinned versions (tested together): Python 3.12, Django 5.2.17, DRF 3.18.1, Celery 5.6.3, redis-py 8.1.0, Channels 4.3.2, psycopg 3.3.6, pydantic 2.13.5, React 18.3, Vite 6.4, TypeScript 5.9, Vitest 3.2, PostgreSQL 16 (timescaledb-ha image with PostGIS), Redis 7.4, Nginx 1.27. | Spec A2 requires exact pins. |
| 2026-10-01 | `nginx/snippets/proxy.conf` does not set `proxy_read_timeout`. | Setting it there duplicated the directive in the WebSocket location, and `nginx -t` rejected the config. |
| 2026-10-01 | Own JWT implementation (PyJWT, HS256) instead of djangorestframework-simplejwt. | Spec A8 needs refresh tokens bound to a server-side session with rotation **and** whole-session revocation on reuse, plus access tokens rejected immediately after logout. simplejwt does not provide reuse detection. The implementation is small and fully tested. |
| 2026-10-01 | Access tokens are validated against the live `UserSession` on every request (one indexed lookup). | Logout, "sign out other devices", password change and reuse detection take effect immediately instead of up to 10 minutes later. |
| 2026-10-01 | Row-Level Security is enforced through a restricted runtime role (`SET ROLE gps_app` on each web connection) and transaction-local `app.current_org` with `ATOMIC_REQUESTS`. | PostgreSQL superusers and table owners bypass RLS. The Docker image's database user is a superuser, so RLS would otherwise be decorative. Transaction-local settings cannot leak between pooled requests. Migrations, Celery and the gateway use the owner role. |
| 2026-10-01 | The audit log is append-only at three levels: model guard, no update/delete API, and `REVOKE UPDATE, DELETE` from `gps_app`. | Even a compromised web process cannot rewrite history. |
| 2026-10-01 | Authentication events are recorded once per organization the user belongs to. | Each organization's administrators can see their own users' logins and lockouts without seeing other tenants' data. |
| 2026-10-01 | Login failures return one identical message, whether the account is unknown, the password is wrong or the account is locked. Unknown accounts also run a dummy hash. | Prevents account enumeration by message or timing. The message tells a real user about the 15-minute lock. |
| 2026-10-01 | No CORS headers are emitted. The SPA and API share one origin behind Nginx. | The most restrictive CORS policy is none. Future mobile apps use bearer tokens and do not need CORS. |
| 2026-10-01 | The sidebar lists only modules that exist (`NAV_ITEMS`). Later phases append entries. | Avoids dead links and placeholder pages (rule A1.4). |
| 2026-10-01 | Fonts (Barlow, Barlow Semi Condensed) are bundled through @fontsource. | Keeps the strict `default-src 'self'` CSP with no external font hosts. The signage-derived typeface suits a transport product. |
| 2026-10-01 | Frontend pins: react-router-dom 6.30, @tanstack/react-query 5.104, zustand 5.0, axios 1.20, i18next 24.2, react-i18next 15.7, react-hook-form 7.89, zod 3.25, tailwindcss 4.3, eslint 9, typescript-eslint 8. Backend adds PyJWT 2.10.1 and drf-spectacular 0.28.0. E2E uses Playwright 1.56. | Spec A2. |
| 2026-10-01 | No GeoDjango. PostGIS is used through SQL (generated geography column, ST_ functions) in migrations and repository queries. | GeoDjango needs the GDAL C library (more than 100 MB in the image, and painful on Windows). Positions are written by the gateway with plain SQL anyway. |
| 2026-10-01 | `positions` is created with raw SQL; the Django `Position` model is unmanaged and read-only. | A hypertable's primary key must include the time column, which the ORM cannot declare. |
| 2026-10-01 | **Positions keep compression; tenant isolation for them uses privileges plus a view instead of RLS.** `gps_app` has no privileges on `positions`; it reads the `tenant_positions` security-barrier view, which applies the RLS predicate. | TimescaleDB 2.17 refuses compression on a table with row security, and RLS on a compressed hypertable, in either order (tested). Compression is essential at millions of rows. The view keeps database-level isolation, which is verified on compressed chunks, and keeps chunk exclusion, verified with EXPLAIN. |
| 2026-10-01 | Foreign keys from `positions` to organizations, devices and vehicles are kept (DEFERRABLE). | Integrity per spec A9. Revisit only if ingest load tests (Phase 11) show they are a bottleneck. |
| 2026-10-01 | A positions migration without TimescaleDB stops with an error unless `REQUIRE_TIMESCALEDB=0`. | No silent fallback to a plain table in a real deployment. |
| 2026-10-01 | Tracker identifiers are unique platform-wide through a partial unique index (`deleted_at IS NULL`). Conflicts are reported without naming the owner. | Spec A7: one IMEI can never belong to two organizations, and other tenants must not be revealed. Retired trackers free their IMEI. |
| 2026-10-01 | Unscoped tenant querysets raise on evaluation, not on construction (`ScopelessQuerySet`). | DRF builds uniqueness-validator querysets when a serializer class is set up, which crashed OpenAPI generation. Every read and write path still raises (tested). |
| 2026-10-01 | A "catalog" tenant policy for shared platform data. | Device models must be readable by every organization (Add Device), but writable only by Super Administrators. The automatic isolation test checks this policy. |
| 2026-10-01 | One generic `ResourcePage` and form generator for all list and edit pages. | Spec A1.8 (no repeated logic). Each resource is a short config of columns, fields and actions. |
| 2026-10-01 | Blank optional numbers, dates and relations are sent as `null` only for fields marked `allowNull`; otherwise they are omitted so the server default applies. | Sending `null` for non-nullable fields (odometer) broke vehicle creation. |
| 2026-10-01 | Dialogs use `showModal()` and render in a portal on `<body>`. | Non-modal dialogs inside table rows let a pending action close a dialog the user had opened since. Modal dialogs also give a focus trap, Esc and a backdrop. |
| 2026-10-01 | Compose pre-publishes 5023, 5055 and 5100–5109 (TCP and UDP) for the gateway. | Docker cannot publish ports at runtime. Spec A7 reserves a range for listener ports assigned in the UI. |
| 2026-10-01 | `THROTTLE_LOGIN` is configurable (production 10/min; CI browser tests 200/min). | The browser suite signs in more often than the production limit allows. |
| 2026-10-01 | The one test that compresses chunks runs with real commits (`transaction=True`, `available_apps` for a CASCADE flush). | Rolling back a transaction that ran `compress_chunk` leaves stale relation-cache entries in the test session. Production compresses in committed background jobs. |
| 2026-10-01 | The gateway writes with the database owner role (asyncpg), not the RLS-restricted `gps_app`. | It is trusted infrastructure that must write `positions` (no access for `gps_app` by design) and always stamps the organization from the registry. |
| 2026-10-01 | Live state is updated in the same transaction as positions; its position fields only move forward in device time. | A backlog upload must never drag the live map backwards (spec A4 rule 4), and the live map must never show a position that was not stored. |
| 2026-10-01 | The session re-reads the registry entry (cached) for every packet. | Disable, vehicle reassignment and IO profile edits must apply to the next packet of an already-open connection (spec A7), not only to new connections. |
| 2026-10-01 | Unknown identifiers: 60-second negative cache, plus inbox writes throttled to one per identifier per 10 seconds with aggregated counts. | A device retrying in a loop, or a flood of random IMEIs, cannot hammer the database. |
| 2026-10-01 | Outlier rule: a jump of more than 0.5 km implying more than 300 km/h from the last valid fix. The record is stored but flagged, and doesn't move the reference point. | Spec A4 rule 7; the 0.5 km floor avoids flagging GPS jitter between near-simultaneous fixes. |
| 2026-10-01 | Raw packet logging and connection history are best effort. | Diagnostics must never cost an ACK or a position. |
| 2026-10-01 | `raw_packets` is a hypertable with retention but **no compression**, so it can use RLS. | It's short-lived (14 days), so compression gains little, and RLS stays the simpler isolation mechanism. |
| 2026-10-01 | The gateway's end-to-end test lives in the backend suite. | Only there does the real schema (migrations, hypertables, policies) exist. CI combines its coverage with the gateway's unit tests. |
| 2026-10-01 | Gateway runtime pins: asyncpg 0.31.0, prometheus-client 0.26.0, redis 8.1.0. | Spec A2. |
| 2026-10-02 | Cloning a device model copies its IO profile (new profile, version 1). | A shared profile meant editing a clone's mapping changed the original model's trackers too, contradicting A7 scenario 2.3. |
| 2026-10-02 | Diagnostics stages are derived from stored data (connections, positions, device state), never from client-side assumptions. | A stage must show "done" only when it really happened. |
| 2026-10-02 | The diagnostics WebSocket polls the database every second and pushes only changes, instead of the gateway publishing per-device events. | Few administrators watch at once; this needs no gateway changes and works identically for the REST fallback. Phase 5's live map uses pushed events. |
| 2026-10-02 | Likely-typo hints show only unregistered identifiers within edit distance 2 of the tracker's IMEI. | Helps the most common onboarding failure without exposing other organizations' traffic from the platform inbox. |
| 2026-10-02 | WebSocket connections are origin-checked (`AllowedHostsOriginValidator`) before the ticket is read. | Blocks other websites from using a user's session. A rejected origin leaves the ticket unconsumed, so it can't be burned by an attacker. |
| 2026-10-02 | The live-feed client falls back to REST polling after repeated WebSocket failures or a 4403. | Some corporate proxies block WebSockets; onboarding must still work. |
| 2026-10-02 | Super Administrators register inbox entries through a platform endpoint into a chosen organization, without break-glass. | It's a platform action, recorded in that organization's audit log. Break-glass remains read-only access to tenant data. |
| 2026-10-02 | The Add Device wizard replaces the generic "Add" form for trackers; CSV import and the generic form remain for SIMs, vehicles and drivers. | Spec A7 makes the guided flow with a connection test the way trackers are added. |
| 2026-10-02 | The simulator is a separate package (`gpssim`) that reuses the gateway's encoder, and ships as a Compose service under the `sim` profile. | Packets are byte-identical to the protocol the gateway parses, and the simulator never runs in production by accident. |
| 2026-10-02 | Daphne 4.2.3 is a development-only dependency (Channels' test communicator needs it); production stays on uvicorn. | Spec A2. |
| 2026-10-02 | The processor publishes straight into Django Channels groups (`channels_redis`), with no Django runtime. | Verified to work outside Django; avoids a second pub/sub layer and keeps the WebSocket consumer trivial. |
| 2026-10-02 | The processor owns vehicle status, including the offline/no-GPS sweep (every 15 s), instead of a Celery Beat task. | One component computes status, so record-driven and silence-driven transitions can't race or disagree. |
| 2026-10-02 | Backlog (`is_late`) and outlier records never move the live map. | Spec A4 rule 4 and A12: the live view shows the newest valid fix only. |
| 2026-10-02 | Per-socket batching: newest update per tracker, flushed once per second (`WS_TRACKING_FLUSH`). | Spec A12 batching; bounds browser work regardless of fleet size; measured latency 0.8–1.0 s. |
| 2026-10-02 | The live client resyncs the REST snapshot after every (re)connect and whenever an update names an unknown tracker. | Updates missed while disconnected must not leave stale positions (spec A12); new trackers appear without a reload. |
| 2026-10-02 | Viewport filtering is used only for fleets over 500 vehicles. | With a filter, vehicles outside the view stop updating; for normal fleets, full updates keep everything fresh. |
| 2026-10-02 | Map pages use a `MapAdapter` interface; Leaflet 1.9 with markercluster is the implementation. | Spec A12. MapLibre can replace it by changing `maps/index.ts`. |
| 2026-10-02 | CSP `img-src` allows `https:`. | Any configured tile provider works without editing Nginx; images can't execute script. |
| 2026-10-02 | `MAP_TILE_URL` has no default inside Compose; `.env.example` provides it. | Compose ends `${VAR-default}` at the first `}`, and tile URLs contain `{z}/{x}/{y}`. |
| 2026-10-02 | The gateway and processor log one-line JSON with all `extra` fields. | Structured fields were being dropped, hiding error reasons. |
| 2026-10-02 | The processor recreates its consumer group when Redis reports `NOGROUP`/`UNBLOCKED`. | Redis can lose the stream (restart without persistence); the database stays the source of truth. |
| 2026-10-02 | Browser tests search lists and use UUID suffixes. | The dev database persists across runs; tests must stay correct as data accumulates. |
| 2026-10-02 | Pins: leaflet 1.9, leaflet.markercluster 1.5, recharts 2.15; processor uses channels 4.3.2 / channels-redis 4.3.0 / redis 8.1.0 / asyncpg 0.31.0. | Spec A2. |
| 2026-10-02 | History simplification runs in Python (Douglas–Peucker on a local metric projection), not `ST_Simplify`. | Each kept vertex must keep its timestamp, speed and ignition for playback; SQL line simplification drops attributes. A day (8,640 points) builds well within the latency target. |
| 2026-10-02 | Stop boundaries and ignition changes are never simplified away. | Playback must stand still exactly at stops, and stop pins must sit on the drawn line. |
| 2026-10-02 | The speed chart uses a separate time-sampled series (max per ~600 buckets). | Geometry simplification keeps corners and stop boundaries, not a representative speed sample; using bucket maxima keeps peaks such as overspeeding. |
| 2026-10-02 | Time ranges are half-open `[start, end)`. | Consecutive windows (day-by-day exports) never contain the same point twice. |
| 2026-10-02 | Exports require `routes.view_history` and `reports.export`; `HasTenantPermission` accepts a tuple meaning "all required". | Viewing and bulk-exporting raw location data are different powers (spec A8 role matrix). |
| 2026-10-02 | The export query parameter is `type`, not `format`. | DRF reserves `?format=` for content negotiation and answers 404 for unknown renderers. |
| 2026-10-02 | Playback moves the map cursor imperatively each animation frame and updates React state at most every 100 ms. | Smooth playback without re-rendering the page and chart 60 times a second. |
| 2026-10-02 | History is fetched for a vehicle (positions' `vehicle_id` snapshot), not a tracker. | Spec A4 rule 12: a tracker moved between vehicles must not mix their histories. |
| 2026-10-02 | Tests that use Redis streams or channel groups run on Redis database 15. | A developer's running stack (database 0) would otherwise consume the tests' entries. |
| 2026-10-02 | The spec lives in the repository (`MASTER_SPEC.md`, `PHASE_PLAN.md`), exported from the Doc; agents check scope and done criteria there. | Phase 6 drifted from the spec while the repo held only a link (execution rule A1.1). |
| 2026-10-02 | Route playback offers the spec speeds (0.5x–16x) plus 60x and 300x. | The spec speeds are kept exactly; the faster ones make multi-day ranges watchable. |
| 2026-10-02 | Forced route points are capped at half the point budget, in priority order. | Without a cap, busy long ranges could prevent the simplification loop from converging. |
| 2026-10-02 | Zoomed-in detail uses a `bbox` query returning separately simplified runs inside the area. | Spec A12 "full resolution only for the zoomed-in segment"; runs stop the detail line from jumping across parts of the route that left the view. |
| 2026-10-02 | Route distance counts only segments where the vehicle moves (at 3 km/h or more). | Spec A4 rule 8: GPS drift while standing is not travel. The movement-radius drift filter in trips arrives with Phase 7. |
| 2026-10-02 | The analysis engine is a pure Python state machine per device; the same code runs live and for recompute. | Every A16 processing rule is unit-testable without a database, and replays can't diverge from live results. |
| 2026-10-02 | Engine state is checkpointed as JSON in `processing_checkpoints.state`, in the same transaction as the results. | A crash can't leave results without the state that produced them, so restarts resume mid-trip exactly (tested). |
| 2026-10-02 | Geofence membership is computed in Python on cached geofences (bbox pre-filter), with PostGIS `geography` stored alongside. | Same semantics as `ST_Covers` for city-scale shapes, without a database round trip per point; the geography column serves queries and reports. |
| 2026-10-02 | Late data queues one pending recompute per device, widened by further late records and run after a 30 s quiet period. | A backlog upload arrives in many batches; replaying once avoids repeated work and flapping results. |
| 2026-10-02 | A replay starts at the beginning of any trip open at the window start, and leaves results open at the window end to the live engine. | Trips are never cut in two by a recompute, and live results are never overwritten by a partial replay. |
| 2026-10-02 | The first observation of a geofence establishes membership silently. | Without history, an "enter" at first sight would be false (for example, a vehicle parked inside when tracking starts). |
| 2026-10-02 | The processor runs the recompute, not Celery. | The engine lives in the processor package; one component owns analysis results. |
| 2026-10-02 | Geofence rules are stored now, but drive alerts only from Phase 8. | Spec A10 rules (scope, triggers, schedule) are needed by the alert engine; events are recorded for every geofence regardless. |
| 2026-10-03 | The alert engine runs in the processor next to the analysis engine. | Every signal already passes through it, in the same transaction as the results that caused it; no second consumer is needed. |
| 2026-10-03 | Deduplication is a partial unique index (rule, vehicle, type) where status is not resolved, written with `INSERT ... ON CONFLICT ... DO UPDATE`. | Concurrent processors can't create duplicates; repeats atomically increment the counter. |
| 2026-10-03 | Cooldown is tracked on the alert (`last_notified_at`). Delayed alerts are never notified. | Spec A11. Notifications reflect live events only. |
| 2026-10-03 | Email is queued in `notifications` and sent by a Celery beat task with back-off; in-app is pushed directly by the processor. | The processor has no Celery dependency, and every attempt and error is recorded on the row. |
| 2026-10-03 | Notification text is rendered per recipient language in the processor; the web app re-renders alerts from `message_params`. | Spec A11: messages in the user's language, including after they switch language. |
| 2026-10-03 | Alert rules replace the Phase 7 `GeofenceRule`. | One rule system for administrators; geofence alerts are rules of the geofence types with `params.geofences`. |
| 2026-10-03 | Command delivery commits SENT before writing to the socket, and keeps one outstanding command per tracker. | Fast trackers answer within milliseconds; Teltonika devices process commands sequentially. |
| 2026-10-03 | Read-only command templates may be sent while unverified (labelled "not verified on hardware"); output-control templates must be verified. | Spec A13 forbids unverified *dangerous* commands; FMC920 read-only commands are harmless and needed for diagnostics. |
| 2026-10-03 | The simulator answers commands with Teltonika-style canned replies. | It proves the Codec 12 round trip; real reply content needs a physical FMC920 (human checklist). |
| 2026-10-03 | Reports are a registry of query functions with typed columns; one definition drives the screen, CSV, Excel, PDF, jobs and schedules. | Adding a report is one entry, and every format stays consistent. |
| 2026-10-03 | Exports above 10,000 rows or 31 days become Celery report jobs; links expire after 24 h and files are purged hourly. | Spec A13; bounded request time and storage. |
| 2026-10-03 | Background jobs and schedules run in the organization's scope with RLS (`org_scope`), not with an RLS bypass. | The same isolation guarantees as requests. |
| 2026-10-03 | Behaviour score: 100 minus (overspeed 5, harsh event 3, crash 20) per 100 km, using at least 1 for the 100 km divisor. | A simple, explainable score; the spec names the score but not a formula. |
| 2026-10-03 | Processor change events clear both the geofence and the alert-rule caches. | A rule created in the UI must apply to the very next record. |
| 2026-10-03 | The browser test stack uses Django's file email backend; tests read invitations from that folder (bind-mounted in CI). | Scenario 1 step 1 needs the real invitation link, without an external mail service. |
| 2026-10-03 | Phase 9 is delivered in two parts. | Part A meets the done criteria; part B (analytics, integrations, maintenance, settings, search, health) is the remaining scope. |
| 2026-10-03 | Share links store only a SHA-256 of the token; the public endpoint bypasses RLS but filters by that hash, returns a fixed minimal shape, and is rate-limited. | Spec A13: public, revocable, no other data; a leaked database row can't be turned back into a working link. |
| 2026-10-03 | The header search reads "Find…", distinct from list "Search" boxes. | Two inputs both labelled "Search" confuse people (and broke test selectors). |
| 2026-10-03 | The system health page probes internal health URLs with a 2 s timeout and reports "degraded" with the failing parts. | One page answers "is it working?" without shell access. |
| 2026-10-03 | Webhook events use a transactional outbox (`webhook_events`) written by the processor and the web app; Celery signs and delivers. | The event exists exactly when the result it reports is committed; the processor needs no Celery; stable dedup keys make replays harmless. |
| 2026-10-03 | Webhook secrets are stored in the database (needed to sign), shown once and never returned or logged. | HMAC signing needs the key server-side; the audit log redacts anything named like a secret. |
| 2026-10-03 | Webhook targets must be public https URLs; redirects are not followed. | Stops tenants using webhooks to reach the platform's internal network (SSRF), including via a redirect after the check. |
| 2026-10-03 | API keys authenticate only on `TenantViewSet` routes, act as their creator narrowed to the key's scopes, and are refused on "any member" personal routes. | A leaked key can't change passwords, mint WebSocket tickets, act on another tenant, or outlive its creator's access. |
| 2026-10-03 | Maintenance and SIM-expiry alerts are raised by the web app (`apps/alerts/system.py`), repeating about 80 lines of the processor's rule logic. | They come from dates and service history, not tracker records; the processor has no Django runtime to share code with. Both follow the same rule, dedup, cooldown, recipient, preference and quiet-hour semantics. |
| 2026-10-03 | Maintenance usage since the last service is summed from trips; engine hours are ignition-on time during trips. | Works without an absolute odometer; trips already apply the drift filter. Engine hours outside trips are not counted (documented approximation). |
| 2026-10-03 | Settings store overrides only (platform over built-in, organization over platform); the processor reads them from the database with a 60 s cache dropped on change events. | One source of truth; untouched installations behave exactly as before. |
| 2026-10-03 | Per-organization retention deletes old positions daily by `(id, device_time)` batches; the TimescaleDB retention policy stays as the platform maximum. | Hypertables can't have per-tenant retention policies; `ctid` is not unique across chunks. |
| 2026-10-03 | Analytics from processed results plus one continuous aggregate (`positions_hourly`); distance per day comes from trips. | Window functions (needed for distance) aren't allowed in continuous aggregates; trips already carry filtered distance. |
| 2026-10-03 | GT06 heartbeats are data frames with zero records. | The listener's normal path then ACKs them after the (empty) store, so GT06 needed no listener change (Scenario 3). |
| 2026-10-03 | Generic formats are bound per listener port (text) or addressed by URL slug (HTTP). | A message's identifier can't be read before its format is known; the port or path selects the format. |
| 2026-10-03 | Format validation and the test-parse box run in the gateway (`POST /test-parse` on the internal port), not in Django. | Spec A18 forbids parsing protocols in Django views; one parser serves validation, preview and ingestion. |
| 2026-10-03 | HTTP trackers authenticate with a per-device token (SHA-256 stored) by default; formats may instead allow registered identifiers. | Spec A7: token or allowlisted identifier; identifiers alone are guessable. |
| 2026-10-03 | Data forwarders are Prepared: model, interface and mapping only, inactive by default. | Spec A2; no regulator specification is invented. |
| 2026-10-04 | Backend metrics use `prometheus_client` with a small middleware instead of django-prometheus. | Route-pattern labels keep cardinality bounded; scrape-time platform gauges (devices, queues, stream) fit naturally; one dependency fewer. |
| 2026-10-04 | `/metrics` is not routed by Nginx and accepts an optional bearer token. | Metrics stay on the internal network; the token protects them if a port is ever exposed by mistake. |
| 2026-10-04 | Gateway writes each packet with one statement (CTEs) and refreshes `devices.last_packet_at` at most every 30 s. | Measured 70x lower median ACK latency under load; atomicity is unchanged (one statement); live state stays exact. |
| 2026-10-04 | Save retries up to 3 times on deadlock/serialization failure. | Concurrent first inserts into a new TimescaleDB chunk deadlock; a retry avoids dropping every affected tracker's connection. |
| 2026-10-04 | The processor fills gaps from the database when a device's next streamed record is > 90 s newer than the last analysed one. | Spec A3 (resume from the database after Redis loss) without querying on every batch; parked trackers reporting every few minutes cost one indexed range query each time. |
| 2026-10-04 | A global TCP connection limit (default 10,000) alongside the per-IP limit. | Spec A4.11; protects memory and file descriptors under a flood. |
| 2026-10-04 | Logical nightly dumps plus pgBackRest WAL archiving. | Dumps are simple and drill-tested; WAL archiving gives point-in-time recovery inside the retention window. |
| 2026-10-04 | `npm audit` fails CI at high severity; the 4 moderate React Router 6 / Vitest 4 advisories are accepted and documented. | Their fixes need major upgrades; the app doesn't use SSR hydration, Vitest is development-only, and the open-redirect bypass is blocked by `safeNext`. |
